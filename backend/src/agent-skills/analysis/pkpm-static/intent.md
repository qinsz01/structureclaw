# PKPM Static Analysis

- `zh`: 当用户明确要求使用 PKPM/SATWE 进行结构静力计算、商业引擎复核、设计验算或结果对比时使用。需要本机安装 PKPM，并通过 General Settings / `settings.json` 的 `pkpm.cyclePath` 或环境变量 `PKPM_CYCLE_PATH` 指向 `JWSCYCLE.exe`。
- `en`: Use when the user explicitly asks for PKPM/SATWE structural static analysis, commercial-engine verification, design checks, or result comparison. Requires a local PKPM installation and `pkpm.cyclePath` in General Settings / `settings.json`, or `PKPM_CYCLE_PATH`, pointing to `JWSCYCLE.exe`.
- `zh`: 已接通无刚域、一次加载、无 P-Delta 的线弹性框架路径。刚性楼板可全楼开启或关闭：开启时核对原生主从节点与源楼层，约束平面内 ux/uy/rz，逐节点保留 uz/rx/ry，不引入实体板、面外板刚度或板重。不同楼层混合开关尚不在此范围。显式 E/nu/G 通过原生自定义弹性材料保存并核对，A/I/J 与原生截面读回一致。自重开关、指定工况、重力加速度和正负 Z 方向明确保存，按源模型密度和实际面积生成官方梁柱荷载；关闭原生自动自重避免重复，逐构件核对原生站点荷载差。数值截面也使用源面积，不用参考载体面积。当前完整输出要求竖直柱、水平梁及逐项核对的边界；不适用属性明确拒绝。
- `en`: The accepted linear elastic frame uses one-time loading with rigid offsets and P-Delta disabled. Rigid diaphragms may be enabled or disabled for the whole building. Native master/slave nodes are bound to authored stories; ux/uy/rz share the in-plane constraint while uz/rx/ry remain per-node. No physical plate, out-of-plane plate stiffness or slab weight is added. Mixed per-floor switches are outside this scope. Explicit E/nu/G and native A/I/J are verified. Selfweight retains its switch, source case, gravity magnitude and positive/negative Z direction. Official beam/column loads use authored density and actual section area, with native automatic weight disabled and signed station differences verified per member. Numeric sections use source area rather than carrier area. Complete outputs require vertical columns, horizontal beams and verified boundaries; unsupported properties are rejected.
- `zh`: 矩形柱的两个正交强轴方向通过原生宽高映射保持。纯数值 `custom` 截面可独立指定 A/Iy/Iz/J，当前剪切面积须满足 Asy=Asz=5A/6；在原生前处理之后编译实际构件弹性属性，求解后逐项回读验证。SDK 中的参考正方形仅供建立拓扑，不是用户物理截面，也不得用于规范几何校核。编译输入、源模型哈希和逐构件属性均保留。
- `en`: Both orthogonal strong-axis directions of rectangular columns are preserved through native width/depth mapping. Pure numeric `custom` sections accept independent A/Iy/Iz/J with Asy=Asz=5A/6. Actual elastic member properties are compiled after native preprocessing and verified after solving. The SDK reference square is a topology carrier, not the user's physical section or code-check geometry. Compiled inputs, source-model hashes and per-member properties are retained.
- `zh`: 固定与三向转动释放柱脚均读取原生证据。铰脚在原生前处理后、求解前将被默认钳制的自由转动刚度编译为零；保留前后输入、哈希及求解阶段记录。平移惩罚残差必须满足冻结容差，自由转角取原生输出，反力由完整有符号端力平衡恢复并标明来源。
- `en`: Fixed and three-rotation pinned bases require native evidence. After preprocessing and before solving, the native numerical floor on requested free rotations is compiled to zero, preserving original/compiled input hashes and phase records. Translation penalty residuals must satisfy frozen tolerances. Free rotations come from native output; reactions are explicitly identified as equilibrium recovery from complete signed end forces.
- `zh`: 梁可在 i 端、j 端或两端成对释放局部 ry/rz，保留轴向与扭转。PMCAD 调整梁端点顺序后，通过官方支座 API 按物理端点重新映射，并由保存后回读和原生构件表共同核对；单个弯曲方向、平移及扭转释放不在此范围。
- `en`: Beams support paired local ry/rz releases at i, j, or both ends while retaining axial and torsional stiffness. After PMCAD reorders endpoints, official support codes are mapped back to physical endpoints and checked in saved API data and solver member tables. Single-axis bending, translation and torsion releases are outside this scope.
- `zh`: 普通计算和设计请求分别解释。`run_code_check(provider=auto/native)` 为已验证标准材料和真实截面建立独立设计运行；所需配筋不代表已有配筋合格。原生钢构件检查保留真实超限、控制组合和官方来源。保护层、箍筋牌号及 HRB400/HRB500 主筋必须实际读回；主筋在 PMCAD 自动处理之后、SATWE 前处理之前通过官方 API 写入并重开核对。SATWE 箍筋计算基准固定100 mm。任意实配钢筋校核及未映射设计条件明确拒绝，不更换求解器或修改原输入规避。实际范围见 `docs/native-design-profiles-20261014.md`。
- `en`: Interpret analysis and explicit design separately. `run_code_check(provider=auto/native)` creates a separately bound design run for verified standard materials and physical sections. Required reinforcement does not certify installed bars. Native steel checks retain real failures, controlling combinations and official sources. Cover, stirrup grades and HRB400/HRB500 main bars require effective readback. Main-bar parameters are written through the official API after PMCAD automatic processing and before SATWE preprocessing, then verified after reopening. SATWE uses a fixed 100 mm stirrup design basis. Arbitrary installed-bar checks and unmapped design conditions remain explicit gaps, without changing engines or authored input. See `docs/native-design-profiles-20261014.md` for the accepted scope.
