# Generic model selection and load verification follow-up

The latest generic-only conversation ran on the restarted 919ef74b build. It repeatedly
failed model generation after the user had already confirmed geometry, storey-dependent
columns and edge/interior beam loads. No PKPM analysis or report was produced. The trace
contained 29 tool calls, 52 LLM calls and six corrections across clarification segments.

The framework defects were separate from provider availability:

- Coordinate selectors read x/y/z directly from member records, although members reference
  endpoint nodes. Every coordinate-based column assignment therefore selected nothing.
- Storey IDs generated by operations were namespaced but the diagnostics did not expose
  available IDs. Missing conjunctions also encouraged invalid invented selector fields.
- Strict load checking could not verify the already accepted grouped load records. Repeating
  generation could not repair the unchanged input representation.
- An exhausted operation/physics build returned a normal tool failure, allowing the outer
  agent to route, extract and build again after internal corrections had ended.
- Earlier short confirmation answers lost their proposal context. Builder history also
  included obsolete assistant workarounds and rejected candidates as though they were input.

Selectors now share one schema and implementation across modelling operations and physics
checks. Node coordinates are direct; member coordinates use endpoint midpoints unless start
or end is explicitly selected. Multiple predicates intersect, and parallelTo uses geometric
global-axis alignment. Exact story IDs remain exact: no S3/story3 alias guessing was added.
Unmatched selectors report available IDs. Explicit storyIds mappings preserve authored floor
identities; conflicting or unused duplicate physical storeys are rejected, not deleted.
Story elevation retains the existing V2 meaning: the bottom of the storey.

New load groups can use structured selectors. Existing accepted records can retain their
original values while the configured LLM emits metadata.loadMappings entries referencing
their stable IDs. These entries map identities only. Unknown/duplicate IDs, numerical
overrides, changed explicit targets, incompatible storeys and unsupported scope conversions
fail. Every selected target and case total is checked independently. The original draft is
not rewritten, and matching totals alone cannot hide swapped edge/interior loads. Specialized
builders also undergo this check when given a structured load selector.

The modelling prompt distinguishes a uniform geometry seed from subsequent group assignments.
Confirmed concrete/reinforcement grades are compiled onto referenced concrete members;
confirmed member overrides remain authoritative. There are no grade-name guesses or fixed
C30/HRB400 defaults in this projection. Reinforcement metadata does not require creating
independent analysis members/materials.

Exhausted operation/physics builds checkpoint a terminal receipt. The existing graph guard
then stops queued dependent tools and further outer-agent work. A fresh user message permits
another turn. Identified missing user facts retain their ordinary clarification path.
Answered proposals stay labelled as context; unselected alternatives are not accepted facts.
Only user messages and answered proposal receipts enter builder history, alongside the
canonical draft; obsolete assistant plans and failed candidates are excluded.

The initial reproduction had ten failing assertions. The final isolated real-provider check
used the latest conversation's accepted draft and actual clarification history, without
answering its pending question or writing the conversation. It generated 80 nodes, 153
members and three storeys, with 40 lower columns at 600x600 and 20 upper columns at 500x500,
C30/HRB400 on every concrete member, and 27 verified original load mappings. Applied totals
were 9,423 kN dead and 1,944 kN live. Extraction and building each used one LLM call, without
correction. User settings and the input snapshot were unchanged.

An additional OpenSees numerical probe explicitly refused the model's p_delta=true setting
with ENGINE_INPUT_UNSUPPORTED. The setting was not changed and no engine fallback was used.
This is not a successful solver result and does not replace the requested PKPM calculation.
The PKPM solve, code check and report were not run by this repair task.
